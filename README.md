# Nebula

This is the Nebula Monte Carlo simulator for electron-matter interaction. Full
instructions on how to install and use this software are in the
[documentation](https://nebula-simulator.github.io).

## Version 1.1.0

Updated by Dian Yu, July 2026. Electron lineage and pixel tagging was contributed by Jonathan Choi.

This repository has been updated, compiled, and tested with the following configuration:
  - WSL2 (Ubuntu 24.04 LTS), Intel Core i7-13700KF, 64 GB RAM, NVIDIA GeForce RTX 4080 with 16 GB VRAM
  - CUDA compiler 12.6, HDF5 1.10.10, GNU 13.3.0, CMake 4.2.1

Point CMake to your local HDF5 installation and CUDA toolkit if they are not found automatically,
and set the architecture of your GPU when configuring, for example for compute capability 8.9 (RTX 40 series):

    cmake -DCMAKE_CUDA_ARCHITECTURES=89 ..

You may consult other sources for more details on how to compile the code if needed.
All modifications are marked in the source code; search the repository for 'Jonathan Choi' and 'Dian Yu' to find them.

### New capabilities

The following programs are built:
  - `nebula_gpu`: GPU simulation, outputs detected electrons
  - `nebula_cpu_mt`: multi-threaded CPU simulation, outputs detected electrons
  - `nebula_cpu_edep`: multi-threaded CPU simulation, outputs detected electrons and energy deposits
  - `nebula_cpu_all_events` (new): single-threaded CPU simulation that records every scattering and
    boundary event, for easier plotting of electron interactions

Other changes:
  - The prescan function in `nebula_gpu` now obtains the running and detected counts in a single loop, which significantly speeds it up.
  - The phonon scattering domain can be set in eV for each material using `--phonon-domain`. Skip it to use the default value of 200 eV, or give one value per material in the order of the material files.
  - The initial material of the primary electrons can be set using `--initial-material`. The default is -123 (vacuum).
  - `EPSILON` in `data_types.h` has been increased by an order of magnitude to suppress electrons that leak from the geometry due to 32-bit precision limits.

`--phonon-domain` accepts multiple values and collects everything up to the next `--` flag, so place it
after the positional arguments or follow it with another flag, for example:

    nebula_gpu geometry.tri primaries.pri silicon.mat pmma.mat --phonon-domain 200 100

### Primary electron file (.pri)

Electrons now carry `origin_z`, a lineage tag, and an event ID. Please change the dtype of the primary electrons to:

    electron_dtype = np.dtype([
        ('x',  '=f'), ('y',  '=f'), ('z',  '=f'),  # Position
        ('dx', '=f'), ('dy', '=f'), ('dz', '=f'),  # Direction
        ('E',  '=f'), ('origin_z', '=f'),          # Energy and origin z position
        ('px', '=i'), ('py', '=i'),                # Pixel indices
        ('lineage', '=i'), ('event_id', '=i'),     # Lineage tag and event ID
    ])

The `lineage` and `event_id` fields of the primaries are read but ignored: all primaries start with lineage 0 and event ID 0.

`origin_z` records the z position where the current state of the electron originated, for escape depth statistics:
  - primaries: the value given in the .pri file
  - BSE: the z position where the primary turned around (lineage changed from 0 to 1)
  - SE: the z position where the secondary was generated

### Output files

The detected electron files of all programs follow the dtype

    electron_dtype = np.dtype([
        ('x', '=f'), ('y', '=f'), ('z', '=f'),
        ('dx', '=f'), ('dy', '=f'), ('dz', '=f'),
        ('E', '=f'),
        ('origin_z', '=f'),
        ('px', '=i'), ('py', '=i'),
        ('lineage', '=i')
    ])

The event files of `nebula_cpu_all_events` (`--events-filename`, extended from the deposit output) follow the dtype

    dtype = np.dtype([
        ('x', '=f'), ('y', '=f'), ('z', '=f'),
        ('E', '=f'), ('delE', '=f'), ('origin_z', '=f'),
        ('px', '=i'), ('py', '=i'), ('lineage', '=i'), ('event_id', '=i')
    ])

The energy deposit files of `nebula_cpu_edep` (`--deposit-filename`) follow the same dtype without `origin_z`.

### Event IDs

The event ID is the type of the last event an electron underwent:

    0:   Primary creation
    1:   Elastic scattering
    11:  Elastic scattering with acoustic phonon loss
    12:  Elastic scattering with atomic recoil loss
    2:   Fermi sea excitation (primary, Penn model)
    21:  SE generated by plasmon decay (Penn model)
    22:  SE generated by single excitation (Penn model)
    3:   Sub-bandgap energy loss (Penn model)
    31:  Optical phonon loss (Kieft & Bosch inelastic model)
    4:   Inner-shell excitation (primary)
    41:  SE from inner-shell excitation (Penn model)
    42:  Excitation without momentum conservation (Kieft & Bosch inelastic model)
    991: Detection
    992: SE detection (DETECTOR_LT50)
    993: BSE/TE detection (DETECTOR_GE50)
    994: Termination
    995: Mirror
    996: Transmission through an interface without refraction
    997: Transmission through an interface with refraction
    998: Absorption at an interface
    999: Total internal reflection

The default physics (`physics_config.h`) uses the Penn inelastic model. With the Kieft & Bosch inelastic model,
secondary electrons inherit the event ID of the event that created them (4 or 42).

### Lineage tags

    0:   Primary (moving with dir.z <= 0 since creation)
    1:   BSE (primary whose direction changed to dir.z > 0 after a scattering event)
    11:  SE1 (generated by a primary)
    21:  SE2 (generated by a BSE)
    12:  SE1, 2nd generation
    22:  SE2, 2nd generation
    13:  SE1, 3rd generation and beyond
    23:  SE2, 3rd generation and beyond

Reflection at an interface does not change a primary into a BSE.
